# 익명화

`raw/`의 원본을 읽어서 이름을 지운 사본을 `anonymized/`에 만든다.
주로 팀원3이 쓴다. **말은 쉽게 한다.**

- 입력: `03_validation/raw/` 또는 `07_usertest/raw/` (저장소에 올라가지 않음)
- 출력: 같은 폴더의 `anonymized/` (저장소에 올라감)

---

## 1. 원본 확인

어떤 파일을 익명화할지 사람에게 확인받는다. `raw/` 폴더의 파일 목록을 보여주고
고르게 한다.

**원본은 절대 고치지 않는다.** 읽기만 한다.

## 2. 무엇을 지울지 먼저 보여주고 확인받는다 — 건너뛰지 않는다

파일을 읽고, 개인정보로 보이는 것을 **치환하기 전에** 목록으로 보여준다.

```
다음을 바꾸려고 합니다. 확인해 주세요.

  이름     김○○      → P01
  이름     이△△      → P02
  전화번호 010-****-**** → (삭제)
  이메일   a***@***.com  → (삭제)
  자유응답 3번 문항에 회사명이 들어 있습니다 → 확인 필요

  총 4건 치환 / 1건 사람 판단 필요
```

그리고 묻는다. **"이대로 진행할까요?"**

이 확인이 반드시 필요한 이유:
**원본은 `raw/`에 있어 저장소에 올라가지 않는다.** 즉 다른 팀원은 원본을 볼 수
없고, 잘못 치환해도 나중에 대조할 방법이 없다. 되돌리려면 원본을 가진 사람이
처음부터 다시 해야 한다. 그래서 사람이 눈으로 보는 지점이 여기 하나뿐이다.

애매한 것은 **자동으로 판단하지 않는다.** "이건 사람이 봐야 합니다"라고 표시하고
물어본다. 특히 자유응답에는 이름·직장·학교·지역이 문장 안에 섞여 들어온다.

## 3. 사본 만들기

확인을 받은 뒤에만 `anonymized/`에 저장한다.

- 참가자 번호는 `P01`, `P02` … 순서로 붙인다
- 같은 사람은 파일이 달라도 같은 번호를 쓴다. 이미 번호가 붙은 파일이 있으면
  그 대응을 이어서 쓴다
- 번호 대응표(누가 P01인지)는 **저장소에 만들지 않는다.** 팀원3이 따로 보관한다

## 4. 검사하고 마무리

```
python3 scripts/check_commit_paths.py --all
```

차단 대상이 나오면 멈추고 알린다. 통과하면 만들어진 파일 목록을 보여주고,
"`/save`로 올리시면 됩니다"라고 안내한다. **여기서 자동으로 커밋하지 않는다.**
