# 작업 시작

**말은 쉽게 한다.** 전문 용어를 쓰지 않는다.

## 0. 먼저 — 두 가지를 확인한다. 하나라도 걸리면 1단계로 가지 않는다

```
{ [ -d .git/rebase-merge ] || [ -d .git/rebase-apply ]; } && echo "중간상태" || echo "정상"
git status --porcelain
```

### 0-a. 저장하지 않은 작업이 있는가

`git status --porcelain` 의 출력이 비어 있지 않으면 **여기서 멈춘다.**

이대로 1단계 `git pull --rebase` 를 치면 이 영어 에러가 그대로 나온다.

```
error: cannot pull with rebase: You have unstaged changes.
error: Please commit or stash them.
```

`/save` 에서 이미 겪은 것과 같은 순서 문제다. 커밋되지 않은 수정이 있으면
rebase 가 시작되지 않는다. 카드 하나 고쳐두고 `/save` 를 안 한 채 다음 날
`/start` 를 치면 매번 이 상태가 된다.

**영어 에러를 절대 사람에게 보이지 마라.** 대신 아래를 그대로 안내한다.
변경된 파일 목록을 함께 보여준다.

> 📝 **아직 저장하지 않은 작업이 있습니다.**
>
> 저장 안 된 파일: (실제 파일 목록)
>
> **없어진 것이 아닙니다.** 지난번에 작업하고 `/save`를 안 치신 것뿐입니다.
>
> 먼저 **`/save`** 를 쳐서 이것부터 올리고, 그다음 `/start` 를 다시 쳐주세요.
> 순서를 바꾸면 팀원 작업을 받아오다가 멈춥니다.

**여기서 `git stash` 나 `git checkout --` 을 제안하지 마라.** 사람이 어제 쓴
카드가 사라진다. `/save` 가 유일한 안내다.

### 0-b. 저장소가 중간 상태인가

**"중간상태"가 나오면 여기서 멈춘다.** 앞선 `/save`에서 파일이 겹쳐 멈춰 있는
것이다. 이 상태에서 `git pull`을 치면 영어 에러가 뜨고, `git log`는 방금 만든
작업이 없어진 것처럼 보여준다. 사람이 더 당황한다.

멈추고 아래를 그대로 안내한다.

> ⚠️ **저장소가 아직 중간 상태입니다.**
>
> 지난번 `/save`에서 파일이 겹쳐 멈춘 상태가 아직 남아 있습니다.
>
> **작업한 내용은 사라지지 않았습니다.** 팀장이 한 줄만 치면 원래대로 돌아옵니다.
> 그때까지 다른 명령을 치지 마세요. 팀 단톡에 이 화면을 붙여넣어 주세요.

팀장이 볼 복구 절차는 `00_project/SETUP.md` 2절 "충돌이 났을 때"에 있다.

## 1. 팀원들 작업 받아오기

```
git pull --rebase
```

충돌이 나면 **직접 해결하지 않는다.** 멈추고 아래를 그대로 안내한다.

> ⚠️ **파일이 겹쳤습니다. 여기서 멈춥니다.**
>
> 겹친 파일: (실제 충돌 파일명)
>
> **작업한 내용은 사라지지 않았습니다. 그대로 복구할 수 있습니다.**
> 팀장 답이 올 때까지 다른 명령을 치지 마세요.
> 이 화면을 그대로 팀 단톡에 붙여넣으시면 됩니다.

## 2. 목록 다시 만들기

`01_evidence/index.csv`는 저장소에 올라가지 않는 파일이라 clone 직후에는 없다.
매번 여기서 다시 만든다.

**스크립트가 아직 없을 수 있으므로 반드시 아래 형태로 실행한다.**
파일이 없을 때 파이썬 에러 메시지가 그대로 튀어나오면 안 된다.

```
[ -f scripts/build_index.py ] && python3 scripts/build_index.py || echo "(카드 목록 만들기는 아직 준비 중입니다 — 건너뜁니다)"
```

`python3 scripts/build_index.py`를 그냥 실행하지 마라.

## 3. 그동안 뭐가 바뀌었는지 요약

`git log --oneline -20`을 보고 **3~5줄로** 알려준다.

- 마지막으로 접속한 뒤 팀원들이 추가한 카드와 그 ID
- 새로 정해진 것 (`_meta/decision_log.md`가 바뀌었다면)
- **오늘 해야 할 일** — `00_project/PROJECT_PLAN.md` 4-2절 주차별 일정에서
  오늘 날짜에 해당하는 주차를 찾아 알려준다

## 4. 마감이 가까우면 알린다

PROJECT_PLAN 4-1절의 **고정 날짜 2개**를 확인하고, 오늘부터 3일 이내면
눈에 띄게 알린다.

- 8/21 설문 배포
- 9/11 사용자 테스트 시작

**이 둘 말고는 마감으로 알리지 마라.** 4-2·4-3절의 날짜는 전부 잠정이며,
며칠 밀리는 것은 규칙 위반이 아니다. 잠정 날짜를 마감처럼 알리면 팀이
계획서를 안 믿게 된다. 오늘 할 일을 안내할 때 참고로만 쓴다.

O 카드에는 마감도 장수 기준도 없다. **몇 장을 썼는지로 사람을 비교하지 마라.**
대신 **아직 한 장도 쓰지 않은 사람이 있으면** 리서치 도우미를 돌리기 전에
먼저 쓰라고 알린다. 날짜가 아니라 순서다.
