# 작업 시작

**말은 쉽게 한다.** 전문 용어를 쓰지 않는다.

## 0. 먼저 — 저장소가 중간 상태인지 확인한다

```
[ -d .git/rebase-merge ] || [ -d .git/rebase-apply ] && echo "중간상태" || echo "정상"
```

**"중간상태"가 나오면 여기서 멈춘다.** 앞선 `/save`에서 파일이 겹쳐 멈춰 있는
것이다. 이 상태에서 `git pull`을 치면 영어 에러가 뜨고, `git log`는 방금 만든
작업이 없어진 것처럼 보여준다. 사람이 더 당황한다.

멈추고 아래를 그대로 안내한다.

> ⚠️ **저장소가 아직 중간 상태입니다.**
>
> 지난번 `/save`에서 파일이 겹쳐 멈춘 상태가 아직 남아 있습니다.
>
> **작업한 내용은 사라지지 않았습니다.** 팀장이 한 줄만 치면 원래대로 돌아옵니다.
> 그때까지 다른 명령을 치지 마세요. 팀 단톡에 이 화면을 붙여넣어 주세요.

팀장이 볼 복구 절차는 `00_project/SETUP.md` 2절 "충돌이 났을 때"에 있다.

## 1. 팀원들 작업 받아오기

```
git pull --rebase
```

충돌이 나면 **직접 해결하지 않는다.** 멈추고 아래를 그대로 안내한다.

> ⚠️ **파일이 겹쳤습니다. 여기서 멈춥니다.**
>
> 겹친 파일: (실제 충돌 파일명)
>
> **작업한 내용은 사라지지 않았습니다. 그대로 복구할 수 있습니다.**
> 팀장 답이 올 때까지 다른 명령을 치지 마세요.
> 이 화면을 그대로 팀 단톡에 붙여넣으시면 됩니다.

## 2. 목록 다시 만들기

`01_evidence/index.csv`는 저장소에 올라가지 않는 파일이라 clone 직후에는 없다.
매번 여기서 다시 만든다.

**스크립트가 아직 없을 수 있으므로 반드시 아래 형태로 실행한다.**
파일이 없을 때 파이썬 에러 메시지가 그대로 튀어나오면 안 된다.

```
[ -f scripts/build_index.py ] && python3 scripts/build_index.py || echo "(카드 목록 만들기는 아직 준비 중입니다 — 건너뜁니다)"
```

`python3 scripts/build_index.py`를 그냥 실행하지 마라.

## 3. 그동안 뭐가 바뀌었는지 요약

- 마지막으로 접속한 뒤 팀원들이 추가한 카드와 그 ID
- 새로 정해진 것 (`_meta/decision_log.md`가 바뀌었다면)
- **오늘 해야 할 일** — `00_project/PROJECT_PLAN.md` 4-2절 주차별 일정에서
  오늘 날짜에 해당하는 주차를 찾아 알려준다
