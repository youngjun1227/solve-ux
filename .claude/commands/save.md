# 작업 저장

**말은 쉽게 한다.** 이 커맨드를 쓰는 사람은 Git을 모를 수 있다. 전문 용어를 쓰지 말고,
문제가 생기면 무엇을 하면 되는지 한국어로 알려준다.

---

## 1. 경로 검사 — 가장 먼저, 반드시

```
python3 scripts/check_commit_paths.py --all
```

**`--all`로 돌린다. `--staged`가 아니다.**
`.gitignore`는 이미 추적 중인 파일을 막지 못하기 때문이다. 실제로 `.DS_Store`가
그렇게 저장소에 들어간 적이 있고, staged만 검사했다면 못 잡았을 것이다.

종료 코드로 갈린다. 판정 기준은 `scripts/paths.py`에 있으니 여기에 옮겨 적지 말고
스크립트 결과를 그대로 쓴다.

**`1` — 커밋하면 안 되는 파일이 있다.** 여기서 멈춘다. 스크립트가 알려주는 조치를
그대로 전하고, 커밋도 push도 하지 않는다.

**`2` — 저장소에 올라가지 않는 파일이 있다.** 멈추고 사람에게 확인을 받는다.
스크립트가 어떤 파일이 왜 안 올라가는지, 어디로 옮기면 되는지까지 알려준다.

> "이 파일은 올라가지 않습니다. 위치를 옮기시겠습니까?"

**"괜찮습니다"라고 넘기지 마라.** 사람은 `/save`가 성공하면 자기 파일이 저장된
줄 안다. 안 올라가는 파일이 있으면 반드시 말해야 한다.
옮기겠다고 하면 파일을 옮기고 1번부터 다시 시작한다.
원래 안 올리려던 파일이면 그대로 진행한다.

**`0` — 이상 없음.** 다음 단계로 간다.

## 2. 무엇이 바뀌었는지 확인

`git status`로 변경 파일을 본다.
`03_validation/raw/`, `07_usertest/raw/`, 연락처, 녹화 파일이 보이면 1번에서 이미
걸렸어야 한다. 그래도 보이면 멈추고 팀장에게 알리라고 안내한다.

## 3. 커밋 메시지 만들기

변경 내용을 보고 이 형식으로 만든다.

```
[유형] 요약 — ID범위 (이름)
```

유형: `E` `S` `C` `O` `H` `P` `SOL` `DOC` `SETUP` `FIX`

예시
```
[E] 20대 보험 인식 데스크리서치 — E-401~E-408 (팀원3)
[S] 보험 Tab 메인/상세 화면 분석 — S-204~S-209 (팀원1)
[O] 보험 탭 첫 사용 관찰 — O-301~O-303 (팀원2)
```

이름은 카드의 `author` 필드에서 가져온다. 알 수 없으면 사람에게 묻는다.

### ⛔ Co-Authored-By 를 붙이지 않는다

**커밋 메시지에 `Co-Authored-By: Claude ...` 를 넣지 마라.**
`Generated with Claude Code` 같은 문구도 넣지 마라.
메시지는 위 한 줄 형식과 필요하면 본문 설명까지다. 그게 전부다.

`CLAUDE.md` "커밋" 절 규칙이며, 기본 동작보다 이 규칙이 우선한다.

## 4. 올리기 전 확인 — 건너뛰지 않는다

`git add` 한 뒤, **커밋하기 전에** 다음을 보여주고 확인을 받는다.

- 올라갈 파일 목록 (추가 / 수정 / 삭제 구분)
- 만든 커밋 메시지

목록은 반드시 이렇게 뽑는다.

```
git -c core.quotepath=false diff --cached --name-status
```

`-c core.quotepath=false` 를 빼면 한글 파일명이
`"03_validation/design/\354\204\244\353\254\270..."` 처럼 깨져 나온다.
사람이 목록을 눈으로 보는 지점이 여기 하나뿐인데 읽을 수 없으면 확인이 무의미하다.

### 고친 카드가 누구 것인지 함께 보여준다

목록에 `M`(수정)으로 나온 **카드 파일**이 있으면, 그 카드의 `author` 필드를 읽어서
함께 보여준다. 새로 만든 카드(`A`)는 볼 필요 없다.

**카드 파일만 본다.** 파일명이 `O-###.md` `E-###.md` `S-###.md` `C-###.md`
`X-###.md` `H-###.md` `P-###.md` `SOL-###.md` `M-###.md` 형태인 것만이다.
`.claude/` 아래 프롬프트 파일과 `00_project/` 문서에도 예시 YAML이 들어 있어서,
`author:` 를 그냥 찾으면 엉뚱한 파일이 카드로 잡힌다.

```
M  01_evidence/team/O-101.md   ← 팀장이 만든 카드입니다
M  01_evidence/desk/E-301.md   ← 팀원2가 만든 카드입니다
```

남의 카드가 섞여 있으면 한 줄 덧붙인다.

> ⚠️ 본인이 만든 카드가 아닌 것이 있습니다. 맞게 고치신 것인가요?
> (오타 수정이면 괜찮습니다. 내용을 바꾸셨다면 만든 사람에게 먼저 말씀하세요.)

**막지는 마라.** 회의 중에 대표로 고치는 경우가 정상적으로 있다.
`CLAUDE.md` 파일 소유권 규칙은 사람끼리의 약속이고, 기계는 누가 고쳤는지 모른다.
**아는 것만 보여주고 판단은 사람이 한다.**

그리고 묻는다. **"이대로 올릴까요?"**

이 확인 절차가 필요한 이유: 되돌리기 명령(`git checkout`)이 허용돼 있어서, 의도치
않은 파일이 섞여 들어가면 남의 작업이나 내 작업이 조용히 사라질 수 있다. 사람이
목록을 눈으로 보는 지점이 여기 하나뿐이다.

사람이 "아니오"라고 하면 아무것도 하지 않고 멈춘다.

## 5. 커밋

확인을 받은 뒤에만 `git commit`.

## 6. 팀원들 작업 받아오기 — 커밋 뒤에 한다

```
git pull --rebase
```

**순서가 중요하다. 반드시 커밋한 뒤에 pull 한다.**
아직 커밋 안 된 수정이 남아 있으면 `git pull --rebase`는 이렇게 실패한다.

```
error: cannot pull with rebase: You have unstaged changes.
```

기존 카드의 오타를 고치는 것만으로도 이 상태가 되므로, pull을 먼저 하면
거의 매번 실패한다.

충돌이 나면 **직접 해결하지 않는다.** 멈추고 아래를 그대로 안내한다.

> ⚠️ **파일이 겹쳤습니다. 여기서 멈춥니다.**
>
> 겹친 파일: `_meta/decision_log.md` (실제 충돌 파일명을 넣는다)
>
> **작업한 내용은 사라지지 않았습니다. 그대로 복구할 수 있습니다.**
> 지금 저장소가 중간 상태라서, `git log`를 보면 방금 만든 것이 없어진 것처럼
> 보일 수 있습니다. 실제로는 남아 있습니다.
>
> **팀장 답이 올 때까지 다른 명령을 치지 마세요.** `/start`도 치지 마세요.
> 이 화면을 그대로 팀 단톡에 붙여넣으시면 됩니다.

**"작업한 내용은 사라지지 않았습니다"를 반드시 말한다.** 이 한 줄이 없으면 사람이
당황해서 이것저것 시도하고, 그때 진짜로 잃는다.

팀장이 볼 복구 절차는 `00_project/SETUP.md` 2절 "충돌이 났을 때"에 있다.
`git rebase --abort` 한 줄로 원상복구되고 커밋도 살아 있다.

## 7. push

`git push`.

실패하면 원인을 쉬운 한국어로 설명하고 해결책을 제시한다.
**절대 제안하지 않는 것:** `--force`, `reset --hard`, 그 밖에 되돌릴 수 없는 명령.
해결이 안 되면 "팀장에게 물어보세요"로 끝낸다. 혼자 이것저것 시도하게 두지 않는다.
