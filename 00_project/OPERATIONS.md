# OPERATIONS.md — 팀장 운영 매뉴얼

**대상: 팀장 한 명.** 기술 용어를 씁니다.

- 무엇을 왜 하는지 → `PROJECT_PLAN.md`
- 무엇이 어디에 있는지 → `SETUP.md` (특히 0절 정본 표)
- 왜 이렇게 설계했는지 → `architecture_review.md`
- 팀원이 보는 조작법 → `HOWTO.md`

**이 문서는 "언제 무엇을 돌리고, 깨지면 어떻게 하는가"만 담습니다.**

## 1. 전체 구성 — 무엇이 무엇을 부르는가

```
사람 ──► /커맨드 ──► agent ──► 카드 파일
                └──► scripts/  ──► 검사 결과

CLAUDE.md ─────────► 항상 로드. 모든 계층이 따른다
```

| 계층 | 무엇 | 언제 로드되나 |
|---|---|---|
| `CLAUDE.md` | 절대 규칙·ID·승격 경로·필수 필드·소유권 | **항상** |
| `.claude/commands/` | 사람이 치는 진입점 7개 | 사람이 칠 때 |
| `.claude/agents/` | 격리된 작업자 5개 | 커맨드나 사람이 부를 때 |
| `.claude/skills/` | 공유 절차 1개 | 모델이 필요하다고 판단할 때 |
| `scripts/` | 판정·생성 로직 | 커맨드·agent가 실행 |

### 현재 있는 것

**커맨드 7개**

| | 누가 | 하는 일 |
|---|---|---|
| `/start` `/save` | 전원 | 받아오기 / 올리기 |
| `/anonymize` | 팀원3 | `raw/` → `anonymized/` |
| `/audit` | 팀장 | 기계 검사 |
| `/redteam` | 팀장 | 판단형 감사 |
| `/gate1` `/gate2` | 팀 회의 | **P·M 생성의 유일 경로** |

**agent 5개** — `desk-researcher` `screen-analyst` `competitor-analyst`
`synthesizer` `red-team-auditor`

**Skill 1개** — `evidence-card` (사람 4명 + 리서치 agent 3종이 공유)

**scripts 6개**

| | 역할 |
|---|---|
| `paths.py` | 커밋 가능 경로 **정의처** |
| `check_commit_paths.py` | 실행 껍데기. 0 정상 / 1 차단 / 2 확인필요 |
| `cards.py` | 카드 상수 **정의처** (대역·필수 필드·본문 구조·파싱) |
| `next_id.py` | 대역 내 마지막 +1 |
| `build_index.py` | 카드 → `index.csv` 재생성 |
| `traceability_check.py` | 검사 13개. ERROR 1건이면 exit 1 |

### 엮이는 방식에서 기억할 것 셋

1. **`cards.py`와 `paths.py`가 정의처다.** 검사 스크립트는 그걸 읽어 쓸 뿐 목록을
   따로 갖지 않는다. 필드를 늘리려면 `cards.py`의 `EXTRA_FIELDS`만 고친다
2. **`.gitignore`는 `paths.py`의 수동 사본이다.** 한쪽을 고치면 다른 쪽도 고친다.
   이 저장소에서 유일한 수동 동기화 지점
3. **Skill 호출은 보장되지 않는다.** 그래서 절대 규칙은 `CLAUDE.md`에,
   한 agent만 쓰는 절차는 그 agent 안에 뒀다 (`SETUP.md` 5절 기준)

## 4. 복구 절차

### 파일이 겹쳤을 때 (충돌)

**`SETUP.md` 2절 "🚨 충돌이 났을 때"가 정본이다.** 요약만:

`git rebase --abort` → `reset --soft HEAD~1` → `restore --staged .` →
`checkout -- <겹친파일>` → `pull --rebase` → 팀원이 다시 쓰고 `/save`

**팀원에게 "작업은 사라지지 않았습니다"를 먼저 말할 것.** 그게 절반이다.

### 잘못 만든 카드

**카드는 삭제하지 않는다** (`CLAUDE.md` ID 규칙). 상황별로 다르다.

| 상황 | 조치 |
|---|---|
| 남의 대역 번호로 만듦 (`#9`) | 그 사람과 상의해 **새 번호로 다시 만들고** 원본은 `status: superseded`로 |
| 필수 필드 누락 (`#3` `#5` `#10~13`) | 그냥 채운다. 못 채우면 그 카드는 근거로 못 쓴다 |
| 손으로 만든 P·M 카드 | **파일을 지우고 `/gate1`·`/gate2`로 다시 만든다.** 유일한 삭제 허용 케이스 — 애초에 존재하면 안 되는 카드다 |
| 근거 등급 D인 C 카드 (`#7`) | 캡처를 구해 A로 올리거나, 못 구하면 지운다 |
| 내용이 틀림 | 고친다. `status`만 바꾸는 것은 가설(H)에 해당 |

### 검사가 실패할 때

```
python3 scripts/traceability_check.py     # ERROR 목록 확인
python3 scripts/check_commit_paths.py --all
```

- **ERROR 1건이라도 있으면 Gate를 통과시키지 않는다.** 예외를 만들면 그 뒤로 계속 만든다
- WARN은 판단 대상이다. `#6`(고아 카드)은 **정상적으로 안 묶인 경우가 많다**
- `--all`이 이미 추적 중인 파일까지 본다. `.gitignore`만 믿지 마라

### 개인정보가 커밋됐을 때 — 즉시

```
git rm --cached <파일>        # 추적 해제
python3 scripts/check_commit_paths.py --all   # 다른 것도 있는지
```

**이미 push했다면 되돌릴 수 없다.** history를 지우려면 팀 전원이 clone을
다시 받아야 하고, GitHub 캐시에는 남는다. 그 판단은 상황을 보고 한다.
**그래서 `/save`가 `--all`로 먼저 막는다.**

## 5. 알고 감수한 위험 2가지

### ① Skill 호출은 보장되지 않는다

팀원이 "카드 만들어줘"라고 쳤을 때 `evidence-card`가 안 불릴 수 있다.
그러면 형식이 틀린 카드가 조용히 생긴다.

**완화** — 절대 규칙은 항상 로드되는 `CLAUDE.md`에 두고, 중요한 절차는 Skill이 아니라
커맨드로 감쌌다. 틀린 카드는 `/audit`이 사후에 잡는다(`#12` 공통 필드 등).

**남은 위험** — "반드시 불린다"는 보장은 만들 수 없다.
**주 1회 `/audit`이 이 위험에 대한 실질적 방어다.** 빼먹지 마라.

### ② `.gitignore`와 `paths.py`의 수동 동기화

`.gitignore`는 파이썬을 import 할 수 없어 `paths.py`의 사본이다.
한쪽만 고치면 조용히 어긋난다.

**완화** — 양쪽 주석에 서로를 가리키게 했고, 실제 방어는 `check_commit_paths.py`가
한다. `.gitignore`가 어긋나도 커밋 직전에 걸린다.

**남은 위험** — `.gitignore`만 느슨해지면 파일이 staged까지 갔다가 걸린다.
막히긴 하지만 사람이 한 번 놀란다.

## 6. 검증되지 않은 영역

**여기까지는 전부 가상 데이터와 시뮬레이션이다.** 아래는 확인된 바 없다.

### 실제 사람

- 팀원 3명이 실제로 `/start` `/save`를 쓰는 것 — **8/5 킥오프가 첫 실전**
- 비개발자가 충돌 안내를 보고 실제로 **멈추는지**. 안내는 만들었지만
  사람이 그대로 따를지는 다른 문제다
- 팀원3이 `/anonymize`의 치환 목록을 **눈으로 확인하는지**

### 실전 리서치

- `desk-researcher`가 **로그인이 필요한 자료**를 만났을 때. 사람 요청 경로는
  프롬프트에 있지만 실제로 매끄러운지 미확인
- `competitor-analyst`는 **캡처가 아직 하나도 없다.** 캡처 파일명 규칙이
  실제 촬영에서 지켜질지가 관건
- `synthesizer`를 **카드 100장 이상**에서 돌린 적 없다.
  `index.csv` 요약 기반 읽기가 그 규모에서 버티는지가 8/17의 최대 변수

### 8/16 이후

- 설문 데이터가 들어온 뒤의 `/anonymize` — 실제 응답 파일 형식을 모른다
- `/gate1` `/gate2`는 **한 번도 실행된 적이 없다.** 프롬프트만 있다
- 고아 카드(`#6`) WARN이 카드 200장에서 몇 건 나올지 모른다.
  대량으로 나오면 신호가 묻힌다. **8/17 종합 직후에 실제 비율을 보고 판단한다**

### 그래서

**8/5 킥오프와 8/7 오후 첫 리서치가 실질적인 1차 검증이다.**
그날 나오는 문제를 기록해 두었다가 반영한다.
`08_deliverable/limitations.md`의 "진행 중 추가" 칸이 그 자리다.
