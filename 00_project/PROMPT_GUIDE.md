# 1. 레포가 어떻게 생겼나

## 1-1. 전체 지도

번호가 붙은 폴더는 **프로젝트가 진행되는 순서**입니다.
`01`에서 자료를 모으고 → `02`에서 가설을 세우고 → `03`에서 물어보고 →
`04`에서 진짜 문제를 정하고 → `05~07`에서 고치고 확인합니다.

```
solve-ux/
├── 00_project/          계획서·안내 문서  ← 읽는 곳
├── 01_evidence/         근거 카드         ← 여기가 여러분 작업장입니다
│   ├── team/            O 카드  직접 써보고 느낀 것
│   ├── desk/            E 카드  외부 자료
│   │   └── sources/       다운로드한 PDF 원본
│   ├── screen/          S 카드  SuperSOL 화면 분석
│   ├── competitor/      C 카드  경쟁 앱 분석
│   ├── expert/          X 카드  멘토 확인
│   └── screens/         📷 캡처 이미지가 들어가는 유일한 곳
├── 02_hypothesis/       H 카드  문제 가설 (8/17 회의에서 확정)
│   └── draft/             AI가 만든 초안
├── 03_validation/       설문 (design / raw🔒 / anonymized / analysis)
├── 04_painpoint/        P 카드  진짜 문제  ← /gate1 로만 생성
├── 05_solution/         SOL 카드  개선안
├── 06_prototype/        Figma 링크 / React 코드
├── 07_usertest/         사용자 테스트
│   └── measurement/     M 카드  개선 효과  ← /gate2 로만 생성
├── 08_deliverable/      발표자료, 한계점
├── _meta/               결정 기록, 멘토 질문, 자료 목록
└── scripts/             ⚙️ 자동 검사 도구 — 열어볼 일 없습니다
```

> 🔒 `03_validation/raw/` 와 `07_usertest/raw/` 두 곳은 **저장소에 올라가지 않습니다.**
> 응답자 이름·연락처가 들어 있어서입니다. 폴더는 남아 있으니 어디에 둘지는 알 수 있습니다.

## 1-2. ⚠️ `screen` 과 `screens` 는 다른 곳입니다

| 폴더 | 무엇이 들어가나 |
|---|---|
| `01_evidence/screen/` | **S 카드**(글로 쓴 분석 결과)가 들어갑니다 |
| `01_evidence/screens/` | **캡처 이미지 파일**이 들어갑니다 |

**캡처는 SuperSOL이든 경쟁 앱이든 전부 `screens/` 한 곳**입니다. 파일명으로 구분합니다.
가장 자주 나는 실수라 따로 적어둡니다.

## 1-3. 내가 직접 만드는 것 / 안 만드는 것

| 카드 | 어디에 | 내가 만드나 | 준비물 |
|---|---|---|---|
| **O** 직접 써본 관찰 | `01_evidence/team/` | ⭕ **직접** | 없음 |
| **E** 외부 자료 | `01_evidence/desk/` | ⭕ 직접 또는 도우미 | 원본 자료 |
| **S** SuperSOL 화면 | `01_evidence/screen/` | ⭕ 직접 또는 도우미 | 캡처 |
| **C** 경쟁 앱 | `01_evidence/competitor/` | ⭕ 직접 또는 도우미 | 내가 찍은 캡처 |
| **X** 멘토 답변 | `01_evidence/expert/` | ⭕ **직접** | 회의에서 들은 것 |
| H 문제 가설 | `02_hypothesis/` | ❌ 8/17 회의 | — |
| P 진짜 문제 | `04_painpoint/` | ❌ `/gate1` 만 | — |
| SOL 개선안 | `05_solution/` | 팀장·팀원2 (9월) | — |
| M 측정 결과 | `07_usertest/measurement/` | ❌ `/gate2` 만 | — |

**8월에 여러분이 직접 쓰는 것은 위 다섯 개(O·E·S·C·X)입니다.**
아래 프롬프트 예시도 전부 이 다섯 개에 대한 것입니다.

## 1-4. 번호는 여러분이 정하지 않습니다

| 나 | 내 번호 |
|---|---|
| 팀장 | 100번대 |
| 팀원1 | 200번대 |
| 팀원2 | 300번대 |
| 팀원3 | 400번대 |

**"나는 팀원2야"라고만 말하면** 알아서 자기 대역의 다음 번호를 받아옵니다.
번호는 **종류마다 따로** 셉니다. 팀원3이면 `O-401`, `O-402` … / `E-401`, `E-402` …
`O-401`과 `E-401`이 같이 있어도 정상입니다. 이름은 접두어까지입니다.

# 2. 프롬프트의 뼈대 — 네 조각

어떤 카드든 이 넷을 말하면 됩니다. 순서는 상관없고, 말하듯이 쓰면 됩니다.

| 조각 | 예 | 빠뜨리면 |
|---|---|---|
| ① **내가 누구인지** | "나는 팀원2야" | 번호를 못 정해서 되묻습니다 |
| ② **무슨 카드인지** | "O 카드 만들어줘" | 종류를 되묻습니다 |
| ③ **본 것 그대로** | "카드가 3개였고 AD라고 적혀 있었어" | 카드가 비거나 지어냅니다 |
| ④ **준비물 위치·날짜** | "screens 폴더에 넣었어, 8월 8일에 찍었어" | 검사에서 걸려 처음부터 다시 합니다 |

### 뼈대만 남기면

```
[카드 종류] 카드 만들어줘. 나는 [내 이름]이야.

[본 것을 그대로 — 숫자와 화면 글자를 살려서]

[캡처 파일명 / 출처 / 날짜]
```

### 형식은 신경 쓰지 마세요

파일을 직접 만들거나, YAML을 채우거나, 번호를 세거나, 폴더를 찾을 필요가
**전혀 없습니다.** 본 것만 말하면 됩니다.

# 3. 카드별 프롬프트 예시

## 3-1. O 카드 — 직접 써보고 느낀 것

> ⚠️ **AI 도우미를 돌리기 전에 먼저 쓰세요.** AI 결과를 본 뒤에 쓰면
> 자기 생각인지 AI 생각인지 구분이 안 됩니다. 장수 기준은 없습니다 — 본 만큼 쓰세요.

**준비물이 없습니다. 지금 바로 쓸 수 있는 유일한 카드입니다.**

### 복사해서 쓰는 형태

```
O 카드 만들어줘. 나는 팀원3이야.

보험 탭을 열었더니 위에 카드가 세 개 있었고 전부 'AD' 표시가 있었어.
내 보험은 네 번째 카드였고 '가입한 보험 3건'이라고 적혀 있었어.
내 보험 보려고 들어갔는데 광고부터 봐야 해서 좀 이상했어.
```

### 말할 때 세 가지만

**① 숫자를 세어서 말하세요**

| 이렇게 말하면 | 이렇게 말하세요 |
|---|---|
| "광고가 많았다" | "카드 3개에 AD 표시가 있었다" |
| "한참 걸렸다" | "스크롤을 두 번 내려야 나왔다" |
| "클릭을 여러 번 했다" | "총 3번 클릭했다" |

**② 화면에 적힌 글자는 그대로 말하세요**

> "'보장 공백 확인 필요'라고 적혀 있었고 그게 무슨 뜻인지 설명은 없었어"

다듬지 말고 그대로요. 나중에 그 문구로 검색하게 됩니다.

**③ 느낌도 그냥 말해도 됩니다**

> "좀 이상했어" "짜증났어" "이게 왜 여기 있지 싶었어"

이런 건 알아서 **해석 칸**에 `"~할 가능성이 있다"` 형태로 정리됩니다.
여러분이 표현을 고를 필요가 없습니다.

### 발견이 여러 개면 나눠서 말하세요

**근거 하나 = 카드 한 장**입니다. 세 가지를 봤으면 카드도 세 장입니다.

```
❌ "광고도 많고 용어도 어렵고 청구 버튼도 못 찾겠더라. O 카드 만들어줘."
   → 나중에 "광고 배치가 문제라는 근거가 뭐야?"에 카드를 짚을 수가 없습니다

⭕ "O 카드 세 장 만들어줘. 나는 팀원1이야.

   첫째, 보험 탭 상단 카드 3개가 전부 AD 표시였고 내 보험은 네 번째였어.
   둘째, '보장 공백'이라고 적혀 있는데 설명이 없어서 무슨 뜻인지 몰랐어.
   셋째, 보험금 청구를 찾으려고 했는데 상세 화면까지 들어가서야 나왔어."
```

**한 번에 여러 장을 부탁해도 됩니다.** 발견별로 나눠서 말해주기만 하면 됩니다.

### 기억이 안 나면 채우지 마세요

**짧으면 짧은 게 정직한 것입니다.** 기억나지 않는 세부를 그럴듯하게 채우면
그건 관찰이 아니라 창작이고, 그 카드가 8/17에 가설의 근거가 됩니다.

> "이 부분은 기억이 정확하지 않아. 빼줘."

이렇게 말하면 됩니다.

## 3-2. E 카드 — 외부 자료

**준비물: 원본 자료.** 기사는 근거로 쓰지 않습니다.
기사는 **원본 보고서 이름을 알아내는 단서로만** 씁니다.

### 네 가지가 없으면 카드를 못 만듭니다

**발행기관 · 발행일 · 링크(또는 파일) · 몇 쪽인지**

하나라도 없으면 만들지 않는 것이 규칙입니다. 억지로 만들지 마세요.

### 복사해서 쓰는 형태

```
E 카드 만들어줘. 나는 팀원3이야.

보험연구원 2025년 11월 20일 발간 보고서 12~14쪽 내용이야.
20대 응답자의 61%가 "본인이 가입한 보험의 보장 내용을 정확히 모른다"고 답했어.
30대는 44%, 40대는 29%야.
조사는 25~59세 1,200명 대상이고 2025년 9월에 했대.

링크는 https://www.kiri.or.kr/report/xxxx 이거야.
PDF는 01_evidence/desk/sources/ 에 넣어뒀어.
```

### 숫자는 자료에 적힌 그대로 말해주세요

`61%`를 "약 60%"로, `1,200명`을 "1천여 명"으로 바꾸지 마세요.
사실 칸에는 **자료에 인쇄된 것만** 들어갑니다.

### 한계를 같이 말해주면 카드가 훨씬 강해집니다

E 카드에는 "이 자료의 한계" 칸이 있습니다. 세 가지를 확인해서 말해주세요.

| 확인할 것 | 예 |
|---|---|
| **언제** 조사했나 | "2021년 조사라 그 사이 앱이 바뀌었을 수 있어" |
| **누구를** 조사했나 | "우리 관심은 20대인데 이건 25~59세 조사야" |
| **무엇을** 조사했나 | "보험 전반이고 SuperSOL 얘기는 아니야" |

**왜 중요하냐면** — 25~59세 조사 결과를 "20대는 이렇다"의 근거로 쓰면
발표에서 질문 하나에 무너집니다. 한계를 적어두면 **어디까지 말할 수 있는지**가
정해집니다.

### 원본을 못 구했으면

카드를 만들지 말고 목록에 남깁니다.

```
자료 목록에 남겨줘. 나는 팀원3이야.
컨슈머인사이트 2024년 보험 앱 이용행태 조사를 찾았는데
원본 PDF가 유료라 못 받았어. 요약 기사만 있어.
```

→ `_meta/source_wishlist.md`에 한 줄 들어갑니다. 나중에 학교 계정으로 처리합니다.

## 3-3. 캡처 넣기 — S·C 카드 공통 준비

**S 카드와 C 카드는 캡처가 폴더에 있어야 만들 수 있습니다.**

### ⚠️ 채팅에 붙여넣으면 카드가 안 만들어집니다

붙여넣기는 됩니다. 그런데 카드에는 **"이 캡처를 보고 썼다"는 파일 경로**가
들어가야 해서, 붙여넣기만 하면 검사에서 이렇게 걸립니다.

```
#11 S 카드 스키마 · S 카드 필수 필드 누락: screen
```

**폴더에 먼저 넣으세요.**

### 어디에, 어떤 이름으로

```
01_evidence/screens/
```

**앱을 가리지 않고 형식 하나입니다** (2026-08-11부터).

```
{앱}_{저니번호}_{화면이름}_{순번}_{날짜}.png 또는 .jpg
```

| | 예 |
|---|---|
| SuperSOL | `supersol_2-0_보험탭_01_20260812.png` |
| 경쟁 앱 | `monimo_3-1_보험분석_04_20260810.jpg` |

**저니번호는 내가 앱을 돌아본 순서입니다** (`1-0` 홈 → `2-0` 다음 화면 →
같은 화면에서 다른 버튼을 누르면 `2-1`). 미리 정하지 말고 찍으면서 붙이세요.
**순번은 01, 02처럼 두 자리**로 씁니다.

**날짜를 꼭 넣으세요.** 앱은 9월 전에 바뀝니다. 그리고 나중에 같은 화면을
다시 찍을 때 앞의 것을 덮어쓰지 않고 나란히 남습니다.

> **T 번호는 파일명에 넣지 않습니다.** 한 화면이 여러 Task에 걸치기 때문입니다.
> 어느 캡처가 어느 Task 답인지는 기록지에 적습니다. 나중에 이름을 바꾸는
> 단계도 없습니다 — 처음 넣은 이름이 끝입니다.

### 폴더 위치를 모르겠으면

```
01_evidence/screens 폴더 열어줘
```

그다음 Finder나 탐색기에서 **끌어다 놓으면** 됩니다.

### 📱 아이폰이면 먼저 설정을 바꾸세요

**아이폰 기본 형식(HEIC)은 읽을 수 없습니다.** 그대로 넣으면 그 자리에서 막힙니다.

**설정 → 카메라 → 포맷 → "높은 호환성"** — 찍기 **전에** 바꾸세요.
이미 HEIC로 찍은 게 있으면 맥 미리보기에서 파일 → 내보내기 → PNG로 저장하면 됩니다.

확장자가 `.png` `.jpg` `.jpeg` 중 하나면 됩니다.

## 3-4. S 카드 — SuperSOL 화면 분석

### 복사해서 쓰는 형태

```
S 카드 만들어줘. 나는 팀원1이야.

01_evidence/screens/supersol_보험탭_메인_20260808.png 를 봐줘.
8월 8일에 찍은 거야.
```

### 여러 장을 한 번에

```
S 카드 만들어줘. 나는 팀원1이야.

screens 폴더에 오늘 찍은 보험 탭 캡처 5장 넣었어.
파일명은 supersol_보험탭_*_20260808.png 형태야.
메인 화면 2장이랑 상세 화면 3장이야.
```

**화면별로 카드를 나눠서** 만들어줍니다.

### 특정 관점을 부탁하고 싶으면

```
특히 정보 순서랑 용어 쪽을 봐줘
```

보는 관점은 이런 것들입니다 — 정보 구조 / 화면 이동 / 찾기 쉬움 / 정보 우선순위 /
읽는 부담 / 용어 / 버튼 / 일관성 / 개인화 / 접근성

**전부 채우지는 않습니다.** 한 화면에서 의미 있게 보이는 건 보통 2~4개입니다.
억지로 다 채우면 근거 없는 말이 생깁니다.

### 받고 나서 꼭 하는 일

**캡처를 열어놓고 사실 칸과 대조하세요.** 개수·순서·문구가 화면과 맞는지.
**여러분이 직접 찍었으니 여러분이 가장 잘 압니다.**

```
사실 칸에 "하단 탭이 5개"라고 되어 있는데 캡처에는 4개야. 고쳐줘.
```

읽을 수 없는 게 있으면 이렇게 나오는데, 이건 정상입니다.

> "헤더 우측 아이콘 2개가 뭉개져 무엇인지 읽히지 않습니다. 확인 필요."

무엇인지 알려주면 반영합니다.

## 3-5. C 카드 — 경쟁 앱

> ⚠️ **"토스는 어떻게 해?"라고 물어보면 안 됩니다.**
> 경쟁 앱 화면은 로그인해야 보여서 AI가 볼 수 없습니다.
> 웹에 있는 건 광고 문구뿐이고, 그걸로 답하면 **그럴듯하지만 틀립니다.**
> 발표에서 심사자가 앱을 열어보면 바로 드러납니다.

### 순서를 뒤집습니다 — 내가 먼저 찍습니다

아래 5개를 직접 해보면서 **거치는 화면을 전부** 찍습니다.

| 번호 | 해볼 것 |
|---|---|
| T01 | 내 보험 현황 확인하기 |
| T02 | 부족한 보장 알아보기 |
| T03 | 보험 정보 이해하기 |
| T04 | 나에게 필요한 보험 찾기 |
| T05 | 확인 후 다음 행동하기 |

**중간 단계를 빠뜨리지 마세요.** "몇 단계가 걸리는가"를 비교할 수 없게 됩니다.
순번 `01`, `03`만 있고 `02`가 없으면 "안 찍은 건지" 되묻게 됩니다.

**파일명에 T 번호가 없습니다.** 저니번호(`3-0`)는 찍은 사람이 돌아본 순서일 뿐이라,
어느 저니번호가 어느 T인지는 AI가 알 수 없습니다. 기록지를 가리켜 주세요.

### 복사해서 쓰는 형태

```
C 카드 만들어줘. 나는 팀원2야.

토스 캡처를 screens 폴더에 다 넣었고 기록지도 다 썼어.
01_evidence/competitor/평가지_toss_팀원1.md 랑
01_evidence/screens/README_toss_캡처.md 보고 T별로 묶어줘.
8월 12일에 찍었어.
```

기록지를 아직 안 썼으면 저니번호 ↔ T를 직접 알려주세요.

```
저니번호 3-0이 T02(부족한 보장 알아보기)야. 4장이고 8월 12일에 찍었어.
```

### 비교하는 건 기능이 아니라 '몇 단계로 푸는가'

| | |
|---|---|
| ❌ | "토스는 보장분석 기능이 있다" — 기능 목록은 쓸모가 없습니다 |
| ⭕ | "토스는 T02를 3단계로 처리하고 입력을 요구하지 않는다" |

### 우열을 판정하지 않습니다

"토스 3단계, SuperSOL 5단계"는 **사실**입니다.
"그래서 토스가 낫다"는 **아직 확인 안 된 생각**입니다.
단계가 적은 게 항상 좋은 것도 아닙니다. 그건 사용자에게 물어봐야 압니다.

### 받고 나서 꼭 하는 일

**캡처에 없는 이야기가 있는지 보세요.** 이게 가장 중요합니다.

```
"토스는 보험료 비교 기능도 있다"고 되어 있는데 내가 넣은 캡처에는 그런 화면 없어.
캡처에서 확인되는 것만 남겨줘.
```

## 3-6. X 카드 — 멘토님께 들은 답

### 먼저: 의문이 들면 그때 바로 적어두세요

멘토님을 자주 뵙지 못합니다. 의문은 앱을 쓰다가 생기는데,
그때 안 적으면 정작 뵐 때 기억나지 않습니다.

```
멘토한테 물어볼 거 추가해줘. 나는 팀원2야.

```

→ `_meta/mentor/ask_팀원2.md`에 한 줄 들어갑니다. 파일을 직접 열 필요 없습니다.

### 답을 들었으면 X 카드로

```
X 카드 만들어줘. 나는 팀원2야.

8월 14일에 여쭤봤어.
질문은 "신한은행 탭에 신한라이프 상품이 없는 게 제휴 계약으로 정해진 것인가"였어.
답은 상품 구성은 계약으로 정해져서 못 바꾸지만 노출 순서는 협의 가능하다고 하셨어.
대외비라고는 안 하셨어.
사실을 알려주신 거야.
```

### 네 가지를 꼭 같이 말해주세요

이게 빠지면 카드가 안 만들어지거나 검사에서 걸립니다.

| 말해줄 것 | 왜 |
|---|---|
| **질문을 그대로** | 답만 있으면 무엇에 대한 답인지 나중에 알 수 없습니다 |
| **여쭤본 날짜** | 정책은 바뀝니다. 언제 들은 답인지가 있어야 근거가 됩니다 |
| **사실인지 의견인지** | 이 카드의 핵심입니다. 아래를 보세요 |
| **대외비라고 하셨는지** | 대외비면 발표 자료에 쓰지 않습니다 |

### 사실 / 의견 — 이게 X 카드의 전부입니다

| 멘토님이 알려주신 것 | 어떻게 쓰나 |
|---|---|
| **사실** — "그건 계약으로 정해져서 못 바꿉니다" | 근거로 씁니다 |
| **의견** — "이게 더 낫겠네요" | 참고만 합니다. **가설·개선안의 근거가 아닙니다** |

**애매하면 "의견인 것 같아"라고 말하세요.**
사실을 의견으로 적으면 근거 하나를 못 쓰고 끝나지만,
의견을 사실로 적으면 **확인 안 된 것이 근거가 됩니다.**

의견을 근거로 쓰면 검사 #15가 ERROR로 잡습니다.

### 질문 하나 = 카드 한 장

8개 여쭤봤으면 8장입니다. 회의 하나를 한 장에 몰아쓰면
같은 회의의 3번 질문(사실)과 5번 질문(의견)을 구분할 수 없습니다.

```
X 카드 만들어줘. 나는 팀원2야. 8월 14일 멘토 회의야.
질문이 세 개였어. 각각 카드로 나눠줘.

1) 상품 구성이 계약으로 정해지는지 → 정해진다고 하셨어. 사실이야.
2) 노출 순서를 바꿀 수 있는지 → 협의하면 가능하다고 하셨어. 사실이야.
3) 어떤 순서가 좋을지 → 보장분석을 위에 두는 게 낫겠다고 하셨어. 의견이야.
```

### 멘토님 말씀도 사용자 조사를 대신하지 못합니다

멘토님은 사용자가 아닙니다. 그리고 만든 쪽은 자기가 만든 것이 쓰기 편한지를
가장 알아보기 어렵습니다.

그래서 **판단을 여쭐 때는 우리 결론을 먼저 말하지 않습니다.**
"저희는 합치는 게 낫다고 보는데 어떠세요?"라고 물으면
답이 아니라 **동의**를 받게 됩니다.

```

```

# 5. 이런 프롬프트는 쓰지 않습니다

| 쓰면 안 되는 말 | 왜 | 대신 |
|---|---|---|
| "토스는 보험을 어떻게 보여줘?" | 로그인해야 보이는 화면이라 **지어냅니다** | 직접 찍어서 캡처를 주세요 |
| "이거 문제인지 판단해줘" | 문제인지는 **사용자가 정합니다** | 사실만 정리시키세요 |
| "P 카드 만들어줘" | Gate 1 회의에서만 만들어집니다 | `/gate1` (팀장) |
| "가설 만들어줘" | 8/17 회의에서 정합니다 | 8/17까지 기다립니다 |
| "설문 문항 만들어줘" | 8/19에 팀이 만듭니다 | 8/19 회의 |
| "20대 보험 통계 알려줘" (자료 없이) | 출처 없는 숫자가 나옵니다 | 자료조사 도우미로 **원본을 찾게** |
| "이 화면 문제점 5개 뽑아줘" | 개수를 맞추려고 억지로 채웁니다 | "보이는 것만 정리해줘" |

**공통점:** 전부 **사람이 정해야 할 것을 AI에게 정하라고 시키는 말**입니다.

도우미는 자료를 모으고 정리하는 역할입니다.
무엇이 문제이고 무엇을 고칠지 정하는 건 사람입니다.

### 개수를 지정하지 마세요

"5개 뽑아줘"라고 하면 3개밖에 없어도 5개를 만듭니다. 나머지 2개는 근거가 없습니다.
**"보이는 것만"** 이라고 말하세요.

## 모든 카드 공통

- [ ] **사실 칸**에 "많다 / 복잡하다 / 어렵다"가 없는가 → 숫자로 바꿔달라고 하세요

- [ ] `"~가 문제다"` `"명백히"` `"확실히"` `"사용자는 불편해한다"`가 없는가
- [ ] **한 줄 요약**이 안 열어도 알게 쓰였는가
- [ ] 한 장에 발견이 **하나만** 들어 있는가
- [ ] 번호가 **내 대역**인가

## E 카드

- [ ] **링크를 눌러 원본이 실제로 있는가** ← 가장 중요합니다
- [ ] 숫자가 그 쪽수에 실제로 있는가
- [ ] "이 자료의 한계"가 채워져 있는가 (비어 있는데 몇 년 전 조사면 다시 확인)
- [ ] 기사를 근거로 쓰지 않았는가

## S·C 카드

- [ ] 캡처를 열어놓고 **개수·순서·문구가 맞는가**
- [ ] **캡처에 없는 이야기가 없는가** ← C 카드에서 가장 중요합니다
- [ ] 캡처 날짜가 들어 있는가
- [ ] (C) 단계 수가 캡처 장수와 맞는가

## X 카드

- [ ] 질문 원문이 들어 있는가
- [ ] 사실/의견 구분이 맞는가 (애매하면 의견)
