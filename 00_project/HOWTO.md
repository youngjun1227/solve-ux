# 이렇게 하시면 됩니다 — 팀원용 사용법

**대상: 팀원 전원.** 개발을 몰라도 됩니다.

이 문서는 **"어떻게 하는지"**만 담습니다.
무엇을 왜 하는지는 `PROJECT_PLAN.md`를 보세요. 그쪽이 기준 문서입니다.

> 여기 나오는 것 중 여러분이 외울 것은 **두 개뿐**입니다 — `/start`와 `/save`.
> 나머지는 필요할 때 이 문서를 다시 열면 됩니다.

> 📄 **처음이시면 `START_HERE.md`를 먼저 보세요.** 10분이면 됩니다.
> 이 문서는 그다음에 필요할 때 찾아보는 설명서입니다.

## 1. 처음 한 번만 하는 것

### ① 저장소 받기

팀장이 초대 링크를 보내드립니다. 수락한 뒤, Claude Code를 열고 이렇게 말하세요.

> "solve-ux 저장소를 받아줘"

받고 나면 폴더가 이렇게 생깁니다. 각 폴더가 무엇인지는 `PROJECT_PLAN.md` 6절에 있습니다.

```
00_project   01_evidence   02_hypothesis   03_validation   04_painpoint
05_solution  06_prototype  07_usertest     08_deliverable
```

### ② 첫 `/start` 쳐보기

```
/start
```

이렇게 뜨면 정상입니다.

```
Already up to date.
카드가 아직 없습니다. 빈 목록을 만들었습니다. (01_evidence/index.csv)
```

**"카드가 아직 없습니다"는 에러가 아닙니다.** 아직 아무도 카드를 안 만들었다는 뜻입니다.

### ③ 첫 `/save` 연습해보기

아무 카드나 하나 만들어보고 `/save`까지 한 번 해보세요.
**8/5 킥오프 때 팀장과 같이 해보는 것을 권합니다.** 그날 한 번 해두면 그 뒤로는 막히지 않습니다.

## 2. 매일 하는 것 — 이 두 개가 전부입니다

### 작업 시작할 때

```
/start
```

팀원들이 올린 최신 자료를 받아오고, 그동안 뭐가 바뀌었는지 알려줍니다.

**반드시 작업 전에 치세요.** 안 하면 남이 고친 걸 덮어쓸 수 있습니다.

### 작업 끝낼 때

```
/save
```

내가 만든 파일을 팀 저장소에 올립니다.

올리기 전에 **"이대로 올릴까요?"**라고 물어봅니다. 목록을 눈으로 확인하고 답해주세요.
이때 화면에 이런 게 뜹니다.

```
[경로 검사] 추적 중인 파일 + 새 파일 47건 — 허용 47 / 차단 0
✅ 차단 대상 없음.

A  01_evidence/team/O-401.md
```

`A`는 새로 추가, `M`은 고침이라는 뜻입니다.

**그날 작업이 끝나면 미루지 말고 치세요.** 며칠 미루면 남의 작업과 겹칠 확률이 올라갑니다.

# 3. 카드 만들기

## 3-0. 카드가 뭔가요

**우리가 찾은 자료 한 조각을 적어둔 파일 한 개**입니다.

자료를 문서 하나에 몰아쓰지 않고 여러 장으로 쪼개서 관리합니다.
나중에 "이 주장의 근거가 뭐였지?"를 되짚기 위해서입니다.

카드에는 번호가 붙습니다. **여러분이 정하는 게 아닙니다.**
**"나는 팀원3이야"처럼 자기가 누구인지만 말하면** 알아서 자기 번호를 받아옵니다.

| 나 | 내 번호 |
|---|---|
| 팀장 | 100번대 |
| 팀원1 | 200번대 |
| 팀원2 | 300번대 |
| 팀원3 | 400번대 |

<!-- 이 표의 정본은 PROJECT_PLAN.md 5절이다.
     대역이 바뀌면 PROJECT_PLAN 5절을 먼저 고치고 여기를 맞춘다. -->

번호가 이렇게 나옵니다.

```
O-401
  파일 위치: 01_evidence/team/O-401.md
```

카드는 다섯 종류입니다.

| 종류 | 무엇 | 준비물 |
|---|---|---|
| **O** | 내가 직접 써보고 느낀 것 | 없음 |
| **E** | 외부 자료 (보고서·논문) | 원본 자료 |
| **S** | SuperSOL 화면 분석 | 화면 캡처 |
| **C** | 경쟁 앱 분석 | 내가 직접 찍은 캡처 |
| **X** | 멘토님께 여쭤보고 들은 답 | 회의에서 들은 것 (4-6절) |

## 3-1. 어떤 카드든 지켜야 할 세 가지

### ① 근거 하나 = 카드 한 장

한 파일에 몰아쓰지 마세요. **발견한 것이 3개면 카드도 3장**입니다.

- ❌ "보험 탭을 써봤는데 광고가 많고, 용어도 어렵고, 청구 버튼도 못 찾겠더라" → 카드 1장
- ⭕ 광고 배치 / 용어 / 청구 버튼 → **카드 3장**

**왜:** 나중에 "광고 배치가 문제라는 근거가 뭐야?"라고 물었을 때 카드 하나를
바로 짚을 수 있어야 합니다. 세 가지가 섞인 카드는 짚을 수가 없습니다.

### ② 사실과 해석을 반드시 나눈다 — 가장 중요합니다

카드는 항상 두 칸으로 나뉩니다.

| 칸 | 여기 쓰는 것 | 판단 기준 |
|---|---|---|
| **사실** | 눈으로 본 것, 셀 수 있는 것, 적혀 있는 글자 | **다른 사람이 봐도 똑같이 말할 것** |
| **해석** | 내 생각 | "~할 가능성이 있다"로 끝남 |

**사실 칸에 들어가는 것**

- 개수 — "카드가 3개였다"
- 순서 — "내 보험은 네 번째였다"
- 화면에 적힌 글자 그대로 — `"보장 공백 확인 필요"`
- 눈에 보이는 차이 — "이 글자만 빨간색이었다"

**사실 칸에 들어가면 안 되는 것**

- ❌ "광고가 **너무 많다**" → 많다는 건 내 판단입니다. "3개였다"가 사실입니다
- ❌ "화면이 **복잡하다**" → 셀 수 없습니다
- ❌ "**찾기 어렵게** 되어 있다" → 어려운지는 사용자가 정합니다

**해석 칸은 반드시 이렇게 끝냅니다**

> "~할 가능성이 있다" / "~로 보인다"

이렇게 쓰면 안 됩니다.

> ❌ "사용자는 불편해한다" / "~가 문제다" / "명백히" / "확실히"

**왜 이렇게까지 하나:** 아직 사용자에게 안 물어봤기 때문입니다.
우리가 문제라고 생각한 것과 사용자가 불편해하는 것은 다를 수 있습니다.
자세한 이유는 `PROJECT_PLAN.md` 1절과 6절에 있습니다.

> 💡 **AI가 단정형으로 써주면 고쳐달라고 하세요.**
> "이건 아직 확인 전이니까 가능성 표현으로 바꿔줘"

### ③ 한 줄 요약을 꼭 넣는다

카드 맨 위에 한 줄 요약이 들어갑니다. **카드를 안 열어도 무슨 내용인지 알게** 씁니다.

- ❌ "보험 탭 관찰" → 열어봐야 압니다
- ⭕ "보험 탭 첫 화면 상단 3개가 광고였고 내 보험은 네 번째였다"

**왜:** 8월 중순이면 카드가 수백 장이 됩니다. 그때 이 한 줄만 모아서 봅니다.

## 3-2. O 카드 — 직접 써보고 느낀 것

> ⚠️ **AI 도우미를 돌리기 전에 먼저 하세요.**
> AI 결과를 보고 나서 쓰면 자기 생각이 아니라 AI 생각이 섞입니다.
> **날짜가 아니라 순서가 중요합니다.** 킥오프 직후에 시작하세요.
>
> **몇 장을 써야 한다는 기준은 없습니다.** 본 만큼 쓰세요. 장수를 채우려고 쓴
> 카드는 근거가 되지 않습니다. **이후에도 좋은 관찰이 생기면 언제든 더 만드세요.**
> 마감도 없습니다.

**가장 먼저, 가장 많이 만들 카드입니다. 준비물이 없습니다.**

### 어떻게 하나요

**1단계 — 앱을 켜고 실제로 써보세요.** 목적을 정하고 해보는 게 좋습니다.

- 내가 가입한 보험이 뭔지 확인해보기
- 보장이 부족한 게 있는지 알아보기
- 보험금 청구는 어떻게 하는지 찾아보기

**2단계 — 걸렸던 순간을 기억하세요.** 이런 순간들입니다.

- 뭔가를 찾는 데 시간이 걸렸다
- 무슨 뜻인지 몰라서 멈칫했다
- 예상과 다른 화면이 나왔다
- "이게 왜 여기 있지?" 싶었다
- 다음에 뭘 눌러야 할지 몰랐다

**3단계 — Claude에게 말하세요.** 이렇게 말하면 됩니다.

> "O 카드 만들어줘. 나는 팀원3이야.
>
> 보험 탭을 열었더니 위에 광고 카드가 세 개 있었고, 내 보험은 네 번째에 있었어.
> 광고에는 'AD'라고 작게 적혀 있었고, 내 보험 칸에는 '가입한 보험 3건'이라고
> 나왔어. 내 보험을 보려고 들어갔는데 광고부터 봐야 해서 좀 이상했어."

**본 것을 그대로 말하면 됩니다.** 형식은 알아서 맞춰줍니다.

### 이렇게 만들어집니다

```
## 사실 (내가 실제로 본 것)
보험 Tab을 열었을 때 위에서부터 카드 3개에 "AD" 표시가 있었다.
"내 보험"은 네 번째 카드였고, 그 안에 "가입한 보험 3건"이 표시되어 있었다.

## 내 해석 (내 생각)
내 보험을 먼저 보고 싶은 사용자에게는 순서가 어긋나 있을 가능성이 있다.
```

### 말할 때 도움이 되는 것

**숫자를 세어서 말해주세요.** "많았다"보다 "3개였다"가 훨씬 좋은 카드가 됩니다.

**화면에 적힌 글자는 그대로 말해주세요.** 기억이 안 나면 캡처를 찍어두었다가 보세요.

**느낌도 말해도 됩니다.** "좀 이상했어", "짜증났어" 같은 것도 괜찮습니다.
그건 해석 칸에 "~할 가능성이 있다" 형태로 정리됩니다.

### 좋은 O 카드 / 아쉬운 O 카드

| | 아쉬운 것 | 좋은 것 |
|---|---|---|
| 사실 | "광고가 너무 많았다" | "위에서부터 카드 3개에 AD 표시가 있었다" |
| 사실 | "정보를 찾기 어려웠다" | "내 보험은 네 번째 카드였다" |
| 사실 | "용어가 어렵다" | "'보장 공백'이라고 적혀 있고 설명은 없었다" |
| 해석 | "이건 문제다" | "우선순위가 어긋나 있을 가능성이 있다" |

## 3-3. E 카드 — 외부 자료

**준비물: 원본 자료.** 뉴스 기사는 근거로 쓰지 않습니다.

### 왜 기사는 안 되나요

기사는 원본을 요약하면서 숫자가 바뀌거나 맥락이 빠집니다.
발표에서 "그 숫자 원본이 뭐예요?"라고 물었을 때 답할 수 없게 됩니다.

**기사는 원본을 찾는 단서로만 씁니다.** 기사에서 보고서 이름을 알아낸 다음,
그 보고서를 직접 찾으세요.

### 어디서 찾나요

보험연구원 · 보험개발원 · 금융위원회 · 금융감독원 · 한국소비자원 ·
컨슈머인사이트 · KB경영연구소 · 하나금융경영연구소 · DBpia·RISS(학교 계정)

### 네 가지가 없으면 카드를 못 만듭니다

**발행기관 · 발행일 · 링크(또는 파일) · 몇 쪽인지**

하나라도 없으면 만들지 않는 게 규칙입니다. 없으면 그냥 "못 찾았다"고 말하세요.
따로 적어두고 나중에 처리합니다. **억지로 만들지 마세요.**

### 이렇게 말하세요

> "E 카드 만들어줘. 나는 팀원3이야.
>
> 보험연구원 2021년 이슈보고서 18쪽에 이런 내용이 있어.
> MZ세대의 설계사를 통한 가입 비중이 68%이고 보험사 웹/앱은 14%래.
> 조사는 25~59세 1,200명 대상이야.
> 링크는 https://kiri.or.kr/... 이거야."

### 자료에 적힌 것만 쓰세요

**사실 칸에는 자료에 인쇄된 숫자와 문장만** 들어갑니다.
표본 크기와 조사 시점이 자료에 있으면 함께 적어주세요.

### 한계를 꼭 확인해주세요

E 카드에는 **"이 자료의 한계"** 칸이 있습니다. 다음을 확인해서 말해주세요.

- **언제 조사한 건가요?** 2~3년 전 자료면 그 사이 앱이 바뀌었을 수 있습니다
- **누구를 조사한 건가요?** 우리 관심은 20대인데 25~59세 조사일 수 있습니다
- **무엇을 조사한 건가요?** 보험 전반이지 SuperSOL이 아닐 수 있습니다

**이게 왜 중요하냐면** — 25~59세 조사 결과를 "20대는 이렇다"의 근거로 쓰면,
발표에서 질문 하나에 무너집니다. 한계를 적어두면 **어디까지 말할 수 있는지**가
정해집니다.

## 3-4. 캡처 넣는 법 — S·C 카드 공통

**S 카드와 C 카드는 캡처가 있어야 만들 수 있습니다.** 그래서 먼저 설명합니다.

### ⚠️ 채팅에 붙여넣지 마세요 — 폴더에 파일로 넣어야 합니다

Claude Code 채팅창에 이미지를 붙여넣을 수는 있습니다.
**그런데 그렇게 하면 카드가 안 만들어집니다.**

**이유:** 카드에는 "이 캡처를 보고 썼다"는 **파일 경로**가 들어갑니다.
붙여넣기만 하면 그 경로가 없어서, 카드를 만들어도 검사에서 이렇게 걸립니다.

```
#11 S 카드 스키마 · S 카드 필수 필드 누락: screen
```

그러면 처음부터 다시 해야 합니다. **폴더에 먼저 넣으세요.**

### 어디에 넣나요

```
01_evidence/screens/
```

**SuperSOL 캡처와 경쟁 앱 캡처가 같은 폴더입니다.** 파일명으로 구분합니다.

> 옆에 `01_evidence/screen/`(끝에 `s`가 없는 것)이 있는데 **거기가 아닙니다.**
> 그쪽은 분석 결과 카드가 들어가는 곳입니다.

### 어떻게 넣나요

**맥(Finder)** — 창을 두 개 엽니다. 휴대폰에서 넘긴 캡처가 있는 폴더 하나,
`solve-ux/01_evidence/screens/` 하나. **캡처를 끌어다 놓으면 됩니다.**

**윈도우(파일 탐색기)** — 똑같습니다. 끌어다 놓기.

폴더 위치를 모르겠으면 Claude에게 물어보세요.

> "01_evidence/screens 폴더 열어줘"

### 파일명 규칙

**앱을 가리지 않고 형식 하나입니다** (2026-08-11부터).

```
{앱}_{저니번호}_{화면이름}_{순번}_{날짜}.png 또는 .jpg
```

| | 예 |
|---|---|
| SuperSOL | `supersol_2-0_보험탭_01_20260812.png` |
| 경쟁 앱 | `monimo_3-1_보험분석_04_20260810.jpg` |

**저니번호는 내가 앱을 돌아본 순서입니다.** 홈에서 시작하면 `1-0`, 다음으로 간
화면이 `2-0`, 그 화면에서 다른 버튼을 눌러 갈래가 생기면 `2-1`·`2-0-1` 식입니다.
**미리 정해놓고 찍는 게 아니라 찍으면서 붙이면 됩니다.**

**순번은 01, 02처럼 두 자리로 쓰세요.** 한 자리로 쓰면 목록이 1, 10, 11, 2 순서로
꼬여서 보기 어려워집니다.

> **T 번호(T01~T05)는 파일명에 넣지 않습니다.** 한 화면이 여러 Task에 걸치는 일이
> 많아서입니다. 어느 캡처가 어느 Task 답인지는 **기록지에 적습니다.**
> 그리고 나중에 파일 이름을 바꾸는 단계는 없습니다 — **처음 넣은 이름이 끝입니다.**

**날짜를 꼭 넣으세요.** 두 가지 이유입니다.

1. 앱은 계속 바뀝니다. 언제 찍은 화면인지 없으면 나중에 근거로 못 씁니다
2. **9월에 같은 화면을 다시 찍을 때 앞의 것을 덮어쓰지 않습니다.**
   날짜가 다르면 파일명이 달라져서 나란히 남습니다

### 📱 아이폰이면 먼저 설정을 바꿔주세요

**아이폰 기본 사진 형식(HEIC)은 읽을 수 없습니다.** 그대로 넣으면 그 자리에서 막힙니다.

**설정 → 카메라 → 포맷 → "높은 호환성"** 으로 바꾸세요.
앞으로 찍는 사진이 전부 JPG로 저장됩니다. **캡처를 찍기 전에 바꾸세요.**

이미 HEIC로 찍은 게 있다면, 맥에서 **미리보기**로 열고
**파일 → 내보내기 → 포맷을 PNG나 JPEG로** 바꿔 저장하면 됩니다.

확장자가 `.png` `.jpg` `.jpeg` 중 하나면 됩니다.

## 3-6. C 카드 — 경쟁 앱

> ⚠️ **"토스는 어떻게 해?"라고 AI에게 물어보면 안 됩니다.**
>
> 경쟁 앱 화면은 로그인해야 보여서 AI가 볼 수 없습니다.
> 웹에서 찾을 수 있는 건 광고 문구뿐이고, 그걸로 답하면 **그럴듯하지만 틀립니다.**
> 발표에서 심사자가 앱을 열어보면 바로 드러납니다.

### 그래서 순서를 뒤집습니다

**내가 먼저 앱을 깔고 직접 해보면서 화면을 전부 찍습니다.**

아래 5가지를 순서대로 해보세요. 팀이 미리 정해둔 비교 기준입니다.

| 번호 | 해볼 것 |
|---|---|
| T01 | 내 보험 현황 확인하기 |
| T02 | 부족한 보장 알아보기 |
| T03 | 보험 정보 이해하기 |
| T04 | 나에게 필요한 보험 찾기 |
| T05 | 확인 후 다음 행동하기 |

**한 가지를 할 때 거치는 화면을 전부 찍습니다.** 중간 단계를 빠뜨리면
"몇 단계가 걸리는가"를 비교할 수 없습니다.

### 파일명 규칙

```
monimo_3-1_보험분석_04_20260810.jpg
```

`앱이름_저니번호_화면이름_순번_찍은날짜` 입니다. 넣는 방법과 아이폰 설정은
**3-4**에 있습니다.

**순번을 빠뜨리지 마세요.** 파일명으로 순서를 읽습니다.
01, 03만 있고 02가 없으면 "중간을 안 찍은 건지" 물어보게 됩니다.

**파일명에 T 번호가 없습니다.** 그래서 AI에게 말할 때 **어느 저니번호가 어느
Task인지 알려주셔야** 합니다. 기록지에 적어두셨으면 "기록지 보고 해"라고만
하셔도 됩니다.

### 이렇게 말하세요

> "C 카드 만들어줘. 나는 팀원2야.
>  토스 캡처는 screens 폴더에 다 넣었고, 기록지도 다 썼어.
>  `01_evidence/competitor/평가지_toss_팀원1.md` 랑
>  `01_evidence/screens/README_toss_캡처.md` 보고 T별로 묶어줘.
>  8월 12일에 찍은 거야."

기록지를 아직 안 쓰셨다면 이렇게 직접 알려주셔도 됩니다.

> "저니번호 3-0이 T02(부족한 보장 알아보기)야. 3장이고 8월 12일에 찍었어."

### 비교하는 건 기능이 아니라 '몇 단계로 푸는가'

- ❌ "토스는 보장분석 기능이 있다" → 기능 목록은 쓸모가 없습니다
- ⭕ "토스는 T02를 3단계로 처리하고 입력을 요구하지 않는다"

**같은 목적을 몇 단계로, 어떤 화면으로 해결하는가**를 봅니다.

### 우열을 판정하지 않습니다

"토스가 3단계, SuperSOL이 5단계"는 **사실**입니다.
"그래서 토스가 낫다"는 **아직 확인 안 된 생각**입니다.

단계가 적은 게 항상 좋은 것도 아닙니다. 그건 사용자에게 물어봐야 압니다.

**왜 바로 적냐면** — 멘토님을 자주 뵙지 못합니다. 의문은 앱을 쓰다가,
카드를 쓰다가 생기는데 그때 안 적으면 정작 뵐 때 기억나지 않습니다.
회의 전에 모인 질문을 정리해서 여쭙습니다.

### 답을 들으면 X 카드로 남깁니다

들은 답은 **X 카드**가 됩니다. 저한테 말씀하시면 만들어드립니다.

```
"멘토님이 이렇게 말씀하셨어. X 카드로 만들어줘. 나는 팀원2야.
 8월 14일에 여쭤봤어. 질문은 '신한은행 탭에 신한라이프 상품이 없는 게
 제휴 계약으로 정해진 것인가'였고,
 계약으로 정해져서 못 바꾼다고 하셨어. 대외비라고는 안 하셨어."
```

### 말할 때 네 가지를 꼭 같이 알려주세요

이게 빠지면 카드가 안 만들어지거나, 만들어져도 검사에서 걸립니다.

| 알려줄 것 | 왜 |
|---|---|
| **질문을 그대로** | 답만 있으면 무엇에 대한 답인지 나중에 알 수 없습니다 |
| **여쭤본 날짜** | 정책은 바뀝니다. 언제 들은 답인지가 있어야 근거가 됩니다 |
| **사실인지 의견인지** | 아래 표를 보세요. 이게 이 카드의 핵심입니다 |
| **대외비라고 하셨는지** | 대외비면 발표 자료에 쓰지 않습니다 |

**애매하면 "의견인 것 같아"라고 말하세요.** 사실을 의견으로 적으면 근거 하나를
못 쓰는 것으로 끝나지만, 의견을 사실로 적으면 확인 안 된 것이 근거가 됩니다.

**질문 하나 = 카드 한 장입니다.** 8개 여쭤봤으면 8장입니다.
회의 하나를 한 장에 몰아쓰면 아래 구분이 안 됩니다.
같은 회의에서도 3번 질문은 사실, 5번 질문은 의견일 수 있습니다.

### ⚠️ 멘토님 말씀도 사용자 조사를 대신하지 못합니다

이게 중요합니다.

| 멘토님이 알려주신 것 | 어떻게 쓰나 |
|---|---|
| **사실** — "그건 계약으로 정해져서 못 바꿉니다" | 근거로 씁니다 |
| **의견** — "이게 더 낫겠네요" | 참고만 합니다. **근거가 아닙니다** |

멘토님은 사용자가 아닙니다. 그리고 만든 쪽은 자기가 만든 것이 쓰기 편한지를
가장 알아보기 어렵습니다. 우리가 확인해야 할 건 **사용자가 어떻게 느끼는가**입니다.

그래서 의견을 여쭐 때는 **우리 결론을 먼저 말하지 않습니다.**
"저희는 합치는 게 낫다고 보는데 어떠세요?"라고 물으면
답이 아니라 동의를 받게 됩니다.

## 6. 잘 안 될 때

### "파일이 겹쳤습니다"가 뜰 때 — 가장 중요합니다

이런 화면이 나올 수 있습니다.

```
⚠️ 파일이 겹쳤습니다. 여기서 멈춥니다.

겹친 파일: _meta/decision_log.md

작업한 내용은 사라지지 않았습니다. 그대로 복구할 수 있습니다.
```

**작업이 사라진 게 아닙니다.** 두 사람이 같은 파일을 동시에 고쳐서 잠깐 멈춘 것뿐입니다.

이때 화면에는 방금 만든 것이 없어진 것처럼 보일 수 있습니다. **그래도 남아 있습니다.**

**할 일은 하나입니다.**

1. 이 화면을 그대로 **팀 단톡에 붙여넣기**
2. **다른 명령을 치지 않기.** `/start`도 치지 마세요
3. 팀장이 한 줄 알려주면 그대로 치기 — 30초면 끝납니다

혼자 해결하려고 이것저것 시도하는 게 오히려 위험합니다.

### "아직 저장하지 않은 작업이 있습니다"가 뜰 때

`/start`를 쳤는데 이 안내가 나오는 경우입니다.

```
📝 아직 저장하지 않은 작업이 있습니다.

저장 안 된 파일: 01_evidence/team/O-401.md

없어진 것이 아닙니다. 지난번에 작업하고 /save를 안 치신 것뿐입니다.
```

**지난번 작업이 아직 내 컴퓨터에만 있다는 뜻입니다.** 고장이 아닙니다.

**이렇게 하세요.**

1. `/save` — 지난번 작업을 먼저 올립니다
2. `/save`가 끝나면 `/start`를 다시 칩니다

**순서를 바꾸면 안 되는 이유:** 저장 안 된 것이 있는 상태에서 팀원 작업을
받아오면 두 개가 겹쳐서 멈춥니다. 먼저 내 것을 올리고 받아오면 안 겹칩니다.

> ⚠️ **인터넷에서 본 `git stash` 같은 걸 치지 마세요.**
> 어제 쓴 카드가 눈앞에서 사라집니다. `/save` 하나면 됩니다.

### "이 파일은 저장소에 올라가지 않습니다"가 뜰 때

```
⚠️ 이 파일은 저장소에 올라가지 않습니다. 1건

  03_validation/설문아이디어메모.md
      03_validation/ 아래에서 올릴 수 있는 곳이 아닙니다
      올릴 수 있는 곳: 03_validation/analysis/, anonymized/, design/
```

**파일을 잘못된 자리에 뒀다는 뜻입니다.** 알려주는 폴더로 옮기면 됩니다.
"옮겨줘"라고 말하면 옮겨줍니다.

### "올라가지 않는 파일 N건 — 원래 그런 것이니 괜찮습니다"가 뜰 때

```
올라가지 않는 파일 1건 — 원래 그런 것이니 괜찮습니다.
  03_validation/raw/응답원본.csv
      원본 파일이라 일부러 올리지 않습니다 (개인정보 보호)
```

**이건 정상입니다.** 아무것도 안 하셔도 됩니다.

### 그 밖에 영어 메시지가 뜰 때

**읽지 마시고 그대로 팀 단톡에 붙여넣으세요.** 대부분 30초 안에 해결됩니다.

혼자 Git 명령어를 찾아서 쳐보는 것은 하지 마세요.
위험한 명령은 막아뒀지만, 막히지 않은 것 중에도 헷갈리는 게 있습니다.

## 7. 하면 안 되는 것 세 가지

### ① 남의 번호 카드 고치기

`O-201`은 팀원1 것입니다. 팀원3이 고치면 안 됩니다.
고칠 게 있으면 **그 사람에게 말하세요.**

만들 때도 마찬가지입니다. 자기 번호대만 씁니다.
실수하면 검사에서 이렇게 잡힙니다.

```
#9 ID 대역 위반 · 01_evidence/team/O-402.md
   팀원1의 대역은 200번대인데 O-402 입니다
```

### ② P 카드를 손으로 만들기

`04_painpoint/` 폴더에 파일을 직접 만들지 마세요.

**P 카드(진짜 문제)는 Gate 1 회의에서만 만들어집니다.**
설문으로 확인된 것만 진짜 문제가 된다는 것이 이 프로젝트의 핵심 원칙이라서 그렇습니다.

손으로 만들면 검사에서 잡힙니다. **형식을 완벽하게 채워도 잡힙니다.**

```
#18 게이트 기록에 없는 P·M 카드 · 04_painpoint/P-001.md
   _meta/gate1_record.md 가 없습니다 — /gate1 을 거치지 않고 만들어진 P 카드입니다
```

Gate 1 회의를 하면 회의 기록에 카드 번호가 남습니다. **그 기록에 번호가 없는
P 카드는 회의를 거치지 않았다는 뜻**이라 검사가 걸러냅니다.

같은 이유로 `M` 카드(9/16 Gate 2)도 직접 만들지 않습니다.

### ③ 공용 파일을 동시에 고치기

번호가 없는 파일이 몇 개 있습니다.

```
_meta/decision_log.md          팀 결정 기록
08_deliverable/outline.md      발표 목차
08_deliverable/limitations.md  한계점
```

**이건 다 같이 모였을 때, 한 사람이 대표로** 고칩니다.
두 명이 동시에 손대면 6절의 "파일이 겹쳤습니다"가 바로 납니다.

회의에서 결정을 적을 때는 **한 명이 화면 공유하며 적고 그 사람만 `/save`** 하세요.
