# 의사결정 기록

AI가 여러 안을 제시하고 **팀이 하나를 고를 때마다** 한 줄씩 남깁니다.

이 파일이 "AI가 다 한 프로젝트 아니냐"는 질문에 대한 우리의 답입니다.
무엇을 골랐는지보다 **왜 나머지를 버렸는지**가 중요합니다.

> ⚠️ 번호가 없는 공용 파일입니다. **팀 회의 중에만** 수정합니다.

형식:

```
2026-09-03 | SOL-002 | AI가 3안 제시(요약카드 / 챗봇 / 진단플로우)
           → 2안 제외(개발 범위 초과), 1안 선택
           → 이유: P-001의 "한눈에 파악" 요구에 가장 직접적으로 대응
```

---

```
2026-08-04 | 세팅 | 저장소 구조를 architecture_review.md 기준으로 확정
           → 소유 단위를 폴더에서 ID 대역으로 변경
           → 이유: 01_evidence/team/ 을 4명이 함께 쓰므로 폴더 소유가 첫 주에 깨진다
```

```
2026-08-05 | 진행 순서 | 각자 앱을 써본 뒤 회의에서 문제와 개선 방향을 먼저 도출
           → 자료 조사·설문을 먼저 하고 방향을 정하는 순서를 택하지 않음
           → 이유: 팀원 전원이 이미 앱을 써본 상태였고, 관찰이 흩어지기 전에
             모으는 편이 낫다고 판단. 도출한 방향은 확정이 아니라 검증 대상으로 둔다
             (내용은 _meta/team_conclusions_20260805.md)
```

```
2026-08-08 | 설문 방식 | 가설 검증형 설문으로 진행하기로 함
           → "우리 방향에 유리한 답이 나오도록 문항을 구성하는" 안을 버림
           → 이유: 틀릴 수 없는 문항은 방향의 정당성을 만들어주지 못한다.
             설문지는 발표 부록에 들어가고 유도 문항이 가장 먼저 드러난다.
             대신 가설마다 "이게 틀렸다면 어떤 답이 나오나"를 먼저 정의하고
             그것을 가르는 문항을 만든다. 만드는 쪽(survey-designer)과
             검사하는 쪽(red-team-auditor)을 분리해 둔다
```
